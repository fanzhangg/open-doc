# No editor yet combines Word, markdown and agents

No product found as of October 2026 combines all four of open-doc's core features: a Word-like WYSIWYG editor, a plain `.md` file on disk, persistent anchored comments plus tracked suggestions that the user accepts or rejects, and a CLI or MCP surface that lets external agents like Claude Code work through a wait-for-human loop. Three groups of products each cover part of that set. **Every's Proof** has the full review model (comments, suggestions, character-level provenance, an agent HTTP bridge). Its SDK is MIT-licensed, but documents live on a server in SQLite, not on disk. The new open-source **AI-native WYSIWYG markdown editors** (Markra, VMark, Nimbalyst, DOMD, OpenWriter) edit local `.md` files and accept agent edits, but they show AI changes only as accept/reject diffs during the session, with no persistent comment threads. A crowd of **agent review tools**, most created in 2026 (Roughdraft, md-redline, markdown-claude-review, couplet, Pena, Crit, Plannotator), has built the anchored-comment and blocking-wait loop, but these are review surfaces rather than editors where you open a file and write. Meanwhile, Microsoft Word, Google Docs and Notion all moved between May and August 2026 to "AI proposes, human approves" using comments and tracked changes. That confirms open-doc's interaction model is right. It also shows the incumbents will not provide it for local markdown. open-doc's gap is real but narrow: it would be the first tool to put a sidecar spec, quote-based re-anchoring, an inbox/wait loop and a true WYSIWYG editor in one open-source package. It still needs tracked suggestions, not only comments, to match what users now expect from Word.

## Word, Docs and Notion all made AI a reviewer in 2026

The clearest market signal is that the three dominant document products all moved their AI into the review channel a human editor would use. They did not let it overwrite text. Microsoft's Message Center notice MC1384426 announced worldwide GA from early June to early July 2026 for Copilot in Word on Windows and Mac. It **makes edits "with word-level precision" as tracked changes and "creates, reads, replies to, and manages comments anchored to document text,"** and the features are on by default ([MC1384426](https://mc.merill.net/message/MC1384426)). One caveat: Microsoft's own Agent Mode help page still says Agent Mode "cannot add or modify comments" and cannot accept or reject tracked changes. It also warns that comments can be deleted when the agent rewrites the paragraph they are anchored to ([Agent Mode in Word](https://support.microsoft.com/office/agent-mode-in-word-647d5d14-eaec-4e8a-a574-7cefffa7f8f0)). That page probably predates the 2026 update. Its warning describes exactly the anchoring failure open-doc's re-anchoring is designed to prevent.

Google followed in July 2026. Gemini in Docs can insert reviewer comments, draft replies to open threads, and "suggest updates to document content based on reviewer feedback" as suggested edits the user approves ([Google Workspace Updates](https://workspaceupdates.googleblog.com/2026/07/streamline-collaboration-in-google-docs-with-Gemini-powered-comment-workflows.html)). Press coverage stresses that it never publishes comments or makes permanent changes on its own ([Ubergizmo](https://www.ubergizmo.com/2026/07/google-docs-smart-review-gemini-now-reads-replies-and-edits/)). Notion's August 28, 2026 release, titled "Ask your agent to suggest edits," says "your agents can now propose changes instead of making them directly" ([Notion releases](https://www.notion.com/releases/2026-08-28)). Notion is a knowledge-base app the user explicitly does not want, so it matters here only as evidence of the same convergence. Lex got to this model first: since February 2023, highlighting text makes the AI "leave a comment with a suggestion for a rewrite" ([Lex newsletter](https://buttondown.com/lex/archive/new-in-lex-comments-ai-rewrite)). ChatGPT Canvas added a green/red "show changes" view after users asked for track changes ([VentureBeat](https://venturebeat.com/ai/chatgpts-canvas-now-shows-tracked-changes)).

All of these are closed, store documents in the cloud or a proprietary format, and run their AI only inside the app. No public MCP or agent API for Lex turned up. The incumbents' platform APIs are only now opening up. Google's Docs API reportedly gained programmatic comment and suggestion management around September 30, 2026, although the release-note dates are inconsistent ([Docs API release notes](https://developers.google.com/workspace/docs/release-notes)). Community MCP servers such as mmedum/google-docs-mcp now **default to suggest mode** ([release v2.1.0](https://github.com/mmedum/google-docs-mcp/releases/tag/v2.1.0)). For Word, docx-mcp ([SecurityRonin/docx-mcp](https://github.com/SecurityRonin/docx-mcp)) and safe-docx ([UseJunior/safe-docx](https://github.com/UseJunior/safe-docx)) write tracked changes and comments into `.docx` files. So someone who wants an agent co-author with a Word-like experience can get one today by giving up plain markdown and local-first storage. open-doc's case rests on not making that trade.

## Proof is the nearest full-featured analogue, but it lives on a server

Every launched **Proof** on March 11, 2026 as "an online document editor built for agents and humans to collaborate," aimed at the plans, PRDs and memos that agents write. It is free and needs no login ([Introducing Proof](https://every.to/on-every/introducing-proof)). It has nearly every interaction open-doc wants: agents comment and suggest edits, humans accept, reject or reply, and "every character tracks who wrote it," shown as a green (human) and purple (AI) provenance rail ([proofeditor.ai](https://www.proofeditor.ai/)). External agents are central to the design. Agents connect over plain HTTP, identify themselves with an `X-Agent-Id` header, and install a `proof` skill. The vendor names Claude Code, Codex, OpenClaw and ChatGPT as clients ([proofeditor.ai](https://www.proofeditor.ai/)). The open-source **proof-sdk** (MIT, about 1,120 stars, last push 2026-08-27) includes the editor, a realtime collaboration server, and an agent bridge with routes for `marks`, `comments`, `suggestions`, `rewrite` and `presence`. It also has `/events/pending` plus `/events/ack` polling, which plays the same role as open-doc's `wait` ([EveryInc/proof-sdk](https://github.com/EveryInc/proof-sdk)).

The difference is the file model. Proof's slogan is "Leave .md files behind" ([proofeditor.ai](https://www.proofeditor.ai/)), and the SDK ships a `doc-store-sqlite` package ([proof-sdk](https://github.com/EveryInc/proof-sdk)). You can fetch a document as raw markdown with `Accept: text/markdown`, but the source of truth is the server, not a file in your repo. Every also says the SDK "is a snapshot that lags the hosted product" ([proofeditor.ai](https://www.proofeditor.ai/)), and the repo showed only about ten commits on main. Proof SDK is better treated as a reference design than as a maintained base to fork. Two other server-backed tools follow the same pattern. **MarkDocs** is self-hosted with Docker and PostgreSQL. It uses Yjs, keeps threaded comments anchored to text, supports inline accept/reject suggestions, and has a 23-tool MCP server and a CLI ([markdocs.sh](https://www.markdocs.sh/)). **Comment.io** describes itself as an agent-native editor with per-edit human-versus-AI attribution ([comment-hq/comment.io](https://github.com/comment-hq/comment.io)). All three anchor annotations to editor marks or CRDT positions. Those anchors hold only while every edit goes through the editor, and break when Claude Code edits the `.md` on disk directly. open-doc is built for exactly that case.

## Local WYSIWYG markdown editors added AI diffs, not review threads

The "open a file, edit, done" editors split into two groups. The established open-source editors have not added AI. **MarkText** (MIT, 62.6k stars) came back to life in 2026, after its original developer resumed upstream maintenance in May, and it shipped v0.21.0–v0.21.2 in October. Its README lists no AI features ([marktext/marktext](https://github.com/marktext/marktext); [releases](https://github.com/marktext/marktext/releases)). Zettlr reached 4.x and has reportedly chosen to keep AI out ([Floatboat](https://floatboat.ai/blog/best-markdown-editors)). It is also a source editor with inline rendering, not true WYSIWYG ([Zettlr 4.0](https://zettlr.com/post/zettlr-400-released)). Among closed apps, Typora has no built-in AI ([rywalker.com](https://rywalker.com/research/typora)). iA Writer chose provenance over generation: its Authorship feature fades pasted AI text and stores attribution in an end-of-file block, published as the open "Markdown Annotations" format ([iA Writer 7](https://ia.net/topics/ia-writer-7); [iA Authorship](https://ia.net/writer/support/editor/authorship)). Bear 2.8 reportedly added a CLI, a Claude Connector and an MCP server rather than built-in AI, which is a closed app choosing to be a tool for external agents ([rywalker.com](https://rywalker.com/research/bear-app)). Bear is a notes app, though, and outside the user's scope.

The second group is a wave of new open-source, AI-native WYSIWYG editors from 2025–2026. All are built on Tauri or Electron with React, and all edit plain `.md` on disk. **Markra** (AGPL-3.0, about 917 stars) bills itself as "a WYSIWYG Markdown editor with native AI" with local data. It previews every AI edit for accept, reject or copy, lets you bring your own model including Ollama, and speaks the Agent Client Protocol (ACP) to local agents ([markrahq/markra](https://github.com/markrahq/markra)). **VMark** (ISC, about 841 stars) uses Tiptap/ProseMirror with WYSIWYG and source modes, and has native MCP setup for Claude Code, Codex CLI and others. It describes itself as "vibe-coded" and does not take external PRs ([xiaolai/vmark](https://github.com/xiaolai/vmark)). **Nimbalyst** (MIT, about 1.9k stars) is the most popular. It uses a Lexical editor and shows red/green agent diffs from embedded Claude Code and Codex sessions, but it is really an agent workspace with kanban, worktrees and a terminal ([nimbalyst/nimbalyst](https://github.com/nimbalyst/nimbalyst); [SitePoint](https://www.sitepoint.com/nimbalyst-the-visual-workspace-for-building-with-claude-code-and-codex/)), so it leans toward the code-editor category the user wants to avoid. **DOMD** has a `domd-cli` that streams agent output into a WYSIWYG window, and its editor kernel recently moved from noncommercial to GPL-3.0 licensing ([do-md/domd](https://github.com/do-md/domd)). **OpenWriter** (MIT, 35 stars but 1,241 commits) calls itself "the open-source writing surface for AI agents." Its 24-tool MCP server makes agent edits appear as green, blue and red pending decorations that you accept or reject with a keystroke ([travsteward/openwriter](https://github.com/travsteward/openwriter)). The closed **MDX** ($15) is the most literally Word-like: it has a toolbar and a doc-style view on a plain `.md` file, but its AI is limited to Tab-to-accept ghost text ([hellomdx.com](https://hellomdx.com/)).

None of these offers persistent anchored comment threads. OpenWriter's README never mentions comments, and Markra's review is a preview before the edit is applied. No source showed any of them saving pending suggestions or comments so they survive a restart or so a human can answer them later. Their model is "agent edits, human approves the diff now," not "agent and human hold a conversation pinned to the text." The persistent-comment tradition in markdown lives elsewhere, in CriticMarkup tooling. That includes Obsidian's Track Changes and Agent Comments plugins ([Track Changes](https://community.obsidian.md/plugins/track-changes); [agent-comments](https://github.com/andrewroxby/agent-comments)) and Marked 2's previewer ([Marked 2](https://cdn2.marked2app.com/help/CriticMarkup.html)). None of it is WYSIWYG, and the Obsidian plugins are inside a knowledge-base app. A long-running Mac Power Users thread asking whether a markdown editor with change tracking exists shows that people have wanted this for years ([MPU forum](https://talk.macpowerusers.com/t/does-a-markdown-editor-with-change-tracking-exist/28703)).

## Agent review tools built open-doc's loop, but not a document editor

The tools whose architecture most resembles open-doc came from Claude Code users who wanted to review agent-written plans. **Roughdraft** (454 stars, published under the Lex-Inc GitHub org, no license detected by GitHub) is the closest in workflow. It is a "local-first markdown editor and viewer for working with AI" that runs a localhost server. `roughdraft open file.md --json` **blocks until the human clicks Done Reviewing** and then emits a `review.completed` event. An experimental stdio MCP server lists pending feedback and appends replies ([Lex-Inc/roughdraft](https://github.com/Lex-Inc/roughdraft)). It stores everything inline as CriticMarkup extended with `{id=… by=… re=…}` attributes. Its last push was June 19, 2026, and forks now ship fixes for bugs that "break the review loop" ([moiri-gamboni/roughdraft](https://github.com/moiri-gamboni/roughdraft)). **md-redline** (MIT, 42 stars, about 743 commits) offers rendered, raw and diff views with MCP tools `mdr_request_review`, `mdr_comment`, `mdr_ask` and `mdr_wait`. It stores each comment as JSON inside a hidden HTML comment placed before the anchored text ([dejuknow/md-redline](https://github.com/dejuknow/md-redline)). **couplet** (GPL-3.0, native macOS) keeps comments in a markdown sidecar. Its CLI works even when the app is closed, and `couplet watch` can run as a Claude Code Monitor that wakes the agent only after the user has been quiet for 20 seconds ([malinborn/couplet](https://github.com/malinborn/couplet)). **Pena** (MIT) has `pena feedback wait` and `watch`, ETag preconditions, and distinct exit codes for timeouts, but it stores documents in SQLite ([mshddev/pena](https://github.com/mshddev/pena)).

**markdown-claude-review** (MIT, a VS Code extension, so off-scope as a product but important as a design) has the most rigorous anchoring found. Its sidecar sits at `.review/<path>.review.json`. Each comment stores no line numbers, only a W3C-style text-quote selector with about 48 characters of context on each side plus the heading trail. On every save it re-resolves through a cascade: unique exact match, then context-disambiguated exact match, then a fuzzy match by Sørensen–Dice trigram similarity within the section, then a stricter fuzzy match across the whole document. The default threshold is 0.62, and each thread is labeled **exact** or **drifted**. Both writers merge against disk right before writing ([MagicMicky/markdown-claude-review](https://github.com/MagicMicky/markdown-claude-review)). This descends from the W3C TextQuoteSelector and Hypothesis's fuzzy anchoring ([W3C annotation model](https://www.w3.org/TR/annotation-model/#text-quote-selector); [Hypothesis](https://web.hypothes.is/blog/fuzzy-anchoring/)), and it is the same approach open-doc takes.

The two tools with real adoption review plans and diffs, not prose. **Plannotator** (about 9,421 stars) hooks Claude Code's `ExitPlanMode` and blocks on approve or deny in a browser UI ([backnotprop/plannotator](https://github.com/backnotprop/plannotator)). **Crit** (about 1,211 stars) anchors comments to line ranges and has a `/crit` command that makes the agent wait for review ([tomasz-tomczyk/crit](https://github.com/tomasz-tomczyk/crit)). Their traction shows that a blocking human-review step for coding agents is now an established pattern. Every one of these tools leaves editing to something else: they are viewers or annotators, not Word-like editors. The exceptions are **Prose** (MIT, Electron with TipTap), whose unmerged PR #854 adds nine MCP review tools, an append-only event log, and a rule that final accept/reject stays with the human ([solo-ist/prose PR #854](https://github.com/solo-ist/prose/pull/854)), and Roughdraft's partial editing. Both have far fewer users than the plan reviewers.

Building a Word-like suggestion layer no longer means starting from scratch, and the licensing landscape shapes the choice. **Plate** is MIT and includes AI-diff-to-suggestion (`applyAISuggestions`) and AI comments mapped to ranges (`aiCommentToRange`) ([Plate AI docs](https://platejs.org/docs/ai)). **BlockNote's** turnkey AI review package is "GPL-3.0 OR PROPRIETARY." Underneath, it uses `prosemirror-changeset` and `@handlewithcare/prosemirror-suggest-changes` ([xl-ai package.json](https://unpkg.com/@blocknote/xl-ai/package.json)). The latter's `withSuggestChanges()` turns any transaction into insertion and deletion marks, though its license was not confirmed ([README](https://cdn.jsdelivr.net/npm/@handlewithcare/prosemirror-suggest-changes@0.1.8/README.md)). Tiptap's agent-to-tracked-changes route is a paid add-on, and its Tracked Changes extension is still alpha ([Tiptap pricing](https://tiptap.dev/pricing.md); [Tiptap tracked changes](https://tiptap.dev/docs/ai/ai-toolkit/client/agents/review-changes/tracked-changes)). Among the sources reviewed, only CKEditor explicitly marks AI suggestions as "Outdated" when the document changes underneath them ([CKEditor v48.4.0](https://newreleases.io/project/github/ckeditor/ckeditor5/release/v48.4.0)).

## Conclusion

The closest products to open-doc are three, each missing a different piece. **Proof** has the review model and agent bridge but not local files. **Roughdraft** has the local file, CLI wait loop and suggestions, but inline CriticMarkup and a review-viewer UX instead of a document editor. **markdown-claude-review** has the same sidecar and quote-anchoring design, but lives inside VS Code. The WYSIWYG editors (Markra, VMark, OpenWriter) have the "open a file, edit, done" feel but treat AI edits as diffs to approve now, not a conversation that persists. So open-doc's defensible position is the intersection of these: a true Word-like editor on a plain `.md` file, with persistent anchored threads in a sidecar that external agents reach through a CLI wait loop. Its strongest unique asset is the **published spec and JSON Schema**. No competitor publishes a formal schema for its sidecar or marker format, and the field is fragmented across five incompatible conventions (CriticMarkup, HTML-comment JSON, `.review.json`, markdown sidecars, iA's Markdown Annotations). A neutral, versioned format with CriticMarkup import/export could become the shared format these tools lack, which is worth more than any one feature.

The research also points to concrete design choices. First, **tracked suggestions are now table stakes**: Word, Docs and Notion all made "agent proposes, human accepts" the default in 2026, while open-doc's README describes comment threads and direct agent edits. A suggestion entry in the sidecar (an anchor, a replacement, an author and a status that can go stale) fits the existing schema, and the MIT ProseMirror changeset and suggestion-mark stack can render it without GPL or paid dependencies. Second, the anchoring should expose an **exact/drifted/detached** state in the UI and merge-before-write, as markdown-claude-review does, because agents editing the file on disk is exactly what breaks mark-based tools like Proof and MarkDocs. Third, the wait loop can borrow proven details from tools that already shipped them: couplet's quiet-period debounce before waking the agent, Pena's ETag preconditions, and Prose's document-identity checks. Finally, a thin **stdio MCP wrapper** over the existing CLI would reach the many clients that md-redline, VMark and OpenWriter already serve, without giving up the CLI-first design. The main uncertainty is speed: most competitors are under a year old and change monthly, so this map will be out of date quickly. Roughdraft's slowdown and Proof SDK's lag behind its hosted product suggest no one has claimed the open, local, Word-like position yet.
