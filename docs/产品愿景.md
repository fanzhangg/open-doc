# 产品愿景

## 一句话愿景

让AI agent像同事一样，和你在同一份文档里同时写作

## 背景与问题

文档编辑是计算机最基础最持久的需求。人类的文档协作经历了两个阶段：

- 用户串行协作 （Word为代表）：用户A编辑完word文档，邮件发给用户B，用户B用修订和批注标出改动，再发回用户A审阅
- 文档并行编辑（Google Docs为代表）：用户A和用户B在一个文档里同时编辑内容

现在AI和人类协同写作已经是不可避免的趋势，然而AI和人类的协作还停留在串行阶段：人类在文档或者聊天框评论，AI审阅评论修改文档，再返回给人类。

## 我们的方案

我的产品把AI和人的协作推进到并行阶段：AI不再是聊天框里的工具，而是文档里的一位协作者。人和AI同时在同一份文档上工作，通过评论讨论、各自动手修改，就像两位同事一起审阅一份方案。

## 设计原则

- **熟悉**：界面沿用大家熟悉的“编辑+评论”交互，几乎没有上手门槛；但底层是为AI设计的：文档是本地的纯Markdown文件，评论单独存放，AI通过命令行读取评论、直接修改文件并回复
- **实时**：agent在后台随时待命，你一评论它就开始处理并在评论里回复；你不用停下来等它，可以同时编辑文档的其他部分
- **可控**：评论锚定在你选中的文字上，agent只修改评论涉及的内容，不动无关的章节；每次改动都会在评论里说明，你可以撤销，也可以让agent只提建议、由你决定是否采纳；评论是否解决始终由你决定
- **开放：**开源的文档格式和文档编辑器，永远不用担心被锁在订阅服务里。
- **多智能体：**多个智能体可以在一个文档同时编辑合作。

## 不做什么

- **在线文档**：文档只存在本地，不做云存储
- **多人实时合作**：只做人和AI的协作，不做人和人的实时协同
- **私有的文档格式**：只用纯Markdown
- **知识库**：只专注单篇文档，不做笔记管理
- **聊天界面**：交流都在评论里，不做聊天窗口

## 目标用户

最先服务的是已经在和AI一起写文档的人，他们：

- 希望和AI协作像和真人同事合作一样顺畅，不用在聊天框和文档之间来回复制粘贴
- 主要在本地写作，文档和代码放在一起（比如在GitHub仓库里写README、设计文档）
- 看重开放的标准和软件，不想被锁在某个订阅服务里

## 核心使用场景

- **AI写，人改**：AI起草了一份设计文档，我边读边审阅，在评论里让AI微调具体的段落
- **人写，AI改**：我写了一篇1万字的小说，不想让AI大范围改动把整篇改乱，只让它微调某几个段落
- **和聊天式Agent配合使用**：大改动交给Chat Agent的CLI或桌面应用，小改动直接在文档里评论；这个页面同时也是阅读器

## 竞品与差异化

现有方案大致分四类：

| 类别                   | 代表产品                                          | 优点                                                   | 缺点                     |
| -------------------- | --------------------------------------------- | ---------------------------------------------------- | ---------------------- |
| **在线文档内置AI**         | Google Docs + Gemini、Notion AI、Word + Copilot | 人人并行协作，AI能在文档里多步编辑（Copilot Agent Mode、Notion Agents） | 绑定自家AI；云端、格式私有         |
| **聊天式AI的画布**         | ChatGPT Canvas、Claude Artifacts等              | 对话里直接生成和修改文档                                         | 以聊天为中心；不在本地，没有多人评论     |
| **AI代码编辑器和命令行Agent** | Cursor、VS Code + Copilot、Claude Code等         | 改本地文件，Agent能力强                                       | 为代码设计，不适合长文写作和逐段讨论     |
| **本地Markdown编辑器**    | Obsidian、Typora等，加AI插件                        | 本地、开放格式                                              | AI只是插件，没有评论，接不了外部Agent |

我们的区别：

- **同步协作，而不是异步交接**：现有方案里，人和AI轮流操作：人提要求，等AI改完，再审阅。我们让人和AI同时在同一份文档上工作，AI处理评论时，人可以继续写其他部分，不同等AI修改完。AI也不用等人写完所有评论后再批量修改。
- **评论就是协作接口**：人在文档里评论，AI读评论、改文档、回复，人决定是否解决，而不是在聊天框和文档之间来回切换
- **本地纯Markdown + 开放**：文档就是仓库里的普通文件，评论单独存放，不被任何订阅服务锁住
- **不绑定某个AI，支持多智能体**：任何能跑命令行的Agent都能接入，可以和用户已经在用的Chat Agent配合。多个Agent还能同时在一份文档里工作，如同很多同事和你一起协作。

## 成功指标

- **用户在驾驶位**：整篇文章不被AI牵着鼻子走。衡量agent改动超出评论范围的次数、被用户撤销的比例
- **减少等待**：降低人和AI串行交接的频次。衡量从评论到agent回复的时间，以及人等agent、agent等人的总时长
- **多agent协作**：多个agent像真人同事一样和用户一起写作。衡量有2个及以上agent参与的文档比例、改动冲突的次数
- **写作体验更好**：比Markdown/代码编辑器+AI插件更好。同一写作任务对比完成时间和满意度；看周活跃文档数和留存
- **开放**：比闭源产品更开放的标准。文档在任何Markdown编辑器里都能正常打开；能接入的第三方agent数量

## 路线图

- 单agent和人通过评论的协作体验
- 精细的历史修改视图和管理
- 多agent和人的协作体验
- 精细的agent权限管理和安全防范
